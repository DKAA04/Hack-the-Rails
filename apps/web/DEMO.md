# Wayward: 3-minute walkthrough

Hosted test environment: https://wayward-nine.vercel.app. The completed browser walkthrough was run on **localhost:3000**, using Duffel test mode, Stripe test mode and PostgreSQL, and was confirmed by the owner. Independent read-only checks corroborated captured payment, settled supplier booking, an actual test e-ticket reference and one supplier order/payment. **A fresh hosted-browser return and refresh/revisit are not yet verified.** The steps below are the hosted demo procedure, not a claim that its browser run has already passed. Nothing here is a live ticket sale.

Use one browser window from start to finish: orders open only in the browser session that created them.

Items marked † identify recent frontend improvements included in the final integration. Check https://wayward-nine.vercel.app/api/health/release for the actual deployed SHA; source integration alone does not establish hosted-browser verification.

## What is real, what is test, what isn't available

- **Real:** place lookup (GeoNames, VBB, Duffel airports); Berlin and Brandenburg public timetables (real departures, **unpriced and not bookable**); order storage in PostgreSQL; the order workflow, Stripe reconciliation and supplier reference shown on the order.
- **Test mode:** flights are **Duffel sandbox test offers**: holds, settlement and the e-ticket reference come from Duffel's test environment. Payment is **Stripe test mode**. **No real ticket is issued and no real money moves.**
- **Not available:** rail, coach and ferry **booking** suppliers (none connected); **live ticket sales** of any kind; account sign-in or recovery (orders open only in the originating browser session); flight offers that can't be held first; refunds and changes through Wayward; choosing a time of day; reading a trip typed as a sentence.

## If a step fails live

1. **Wrong place or no airport in the list:** type more of the name (`John F Kennedy`, `Newark Liberty`) and pick the row labelled _Airport_. The place ranking is a known backend issue.
2. **"Price or times changed" or "This offer has expired" before reservation:** refresh results (or edit the search), review a new quote and explicitly accept changes. Use the returned expiry; do not assume every sandbox offer lasts 30 minutes. **A reserve/settlement timeout or manual-review state is different:** inspect the existing order and reconcile its outcome; do not create another order, change its idempotency key or repeat a confirmed purchase.
3. **The return from Stripe doesn't settle:** open **Orders** in the same browser, then the existing order, then **Check again**. Report its order ID and actual state for read-only investigation. Lost-session access and sample previews do not prove fulfillment; do not present a sample as evidence of a completed transaction.
